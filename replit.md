# GSI Partner Opportunity Tracker

A full-stack web app for VP-level alliance/partner sales teams to track GSI partner opportunities and initiatives using the MEDDPICC qualification framework.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 8080)
- `pnpm --filter @workspace/gsi-tracker run dev` — run the React frontend (Vite)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL`, `SESSION_SECRET`

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- API: Express 5 (port 8080 via workflow)
- Frontend: React 18 + Vite + TanStack React Query + Wouter + shadcn/ui + Tailwind CSS 4
- DB: PostgreSQL + Drizzle ORM
- Validation: Zod (`zod/v4`), `drizzle-zod`
- API codegen: Orval (from OpenAPI spec)
- Build: esbuild (CJS bundle)
- Charts: Recharts

## Where things live

- `lib/api-spec/openapi.yaml` — Source of truth for all API contracts
- `lib/db/src/schema/` — Drizzle schema files (users, profiles, partners, opportunities, meddpicc)

## Architecture decisions

- **Auth without bcrypt/express-session**: Both packages were unavailable via pnpm firewall. Auth uses Node built-in `crypto` (scrypt for passwords, HMAC-SHA256 for session cookies). No external auth dependency.
- **Contract-first API**: OpenAPI spec → Orval codegen → typed React Query hooks + Zod schemas. Never hand-write API calls.
- **MEDDPICC score (weighted)**: Auto-recalculated on every meddpicc entry create/update/delete. Each element has a weight (metrics/economic_buyer/identify_pain/champion = 15; decision_criteria/decision_process/paper_process/competition = 10; sum = 100). Per-element strength (0..1) = presence 0.40 + validation 0.40×validatedRatio + relevance 0.20×(avgRelevance/5), relevance defaulting to 3. overallScore = Σ(weight × strength) → 0-100. Weighting + strength helpers live server-side in `artifacts/api-server/src/routes/meddpicc.ts`; the GET response returns per-element `score`/`weight`. Qualification bands (≥75 Strong, 50-74 Moderate, 25-49 Weak, <25 Unqualified) for presentation live in `artifacts/gsi-tracker/src/lib/meddpicc.ts` alongside revised element guidance.
- **Session cookie format**: `userId:timestamp` signed with HMAC-SHA256 using SESSION_SECRET. 7-day TTL enforced server-side.
- **Multi-tenant**: Single-tenant for Phase 1. Admin user (madgh411@gmail.com) can create rep accounts.
- **AI company intelligence (presentation-only)**: At opportunity creation the rep searches/disambiguates the real end-customer company (AI candidate picker → sets `endCustomer`/`endCustomerDomain`). On the opportunity detail page, AI synthesizes grounded corporate context for each of the 8 MEDDPICC elements (split-screen: rep "Micro Focus" entries LEFT, AI company context RIGHT; "View full" popup with sources; Refresh/Generate button). **This corporate context is strictly presentation-only and never affects the weighted MEDDPICC score** — only rep entries score. AI runs via Replit-managed Gemini (no user API key). AI logic lives in `artifacts/api-server/src/lib/companyIntel.ts`; routes in `artifacts/api-server/src/routes/company.ts`. No paid data providers.
- **Admin data backup / import / clear (Profile & Settings)**: Admin-only "Data Management" card on the Profile page. Export downloads a full JSON backup of ALL tables (users incl. password hashes, profiles, partners, opportunities, meddpicc_entries, meddpicc_section_meta, company_research) as a browser download. Import replaces the entire DB from a JSON file (transaction: TRUNCATE … RESTART IDENTITY CASCADE, re-insert preserving ids, then `setval` to re-sync serial sequences). Clear deletes all data but preserves the admin account (deletes partners→cascades opportunities/meddpicc/sections/research; deletes non-admin users→cascades profiles; resets admin profile to defaults). All three are gated by `requireAdmin` (loads user, checks role==='admin'); import refuses any payload whose users array has no admin (lockout guard). Generic raw-SQL round-trip via the pg `pool`: jsonb columns are detected on import by value being an array/plain object and serialized with JSON.stringify (node-pg would otherwise treat JS arrays as Postgres array literals). Backend: `lib/backup.ts` (exportAll/importAll/clearAll), `lib/requireAdmin.ts`, `routes/backup.ts`. No schema change.
- **Structured multi-note lists (add/edit/delete)**: Notes are a shared `Note` model (`{id,text,createdAt}`) across three surfaces — opportunity notes (jsonb `OppNote[]`, gold-standard `NotesSheet` in `dashboard.tsx`), **partner notes** (`partners.notes` jsonb `Note[]`, incl. the new-partner create form), and **MEDDPICC section "additional context"** (`meddpicc_section_meta.notes` jsonb `Note[]`). One reusable controlled `NotesEditor` (`components/notes-editor.tsx`) powers partner + section: add-draft, inline edit, delete; emits full next array via `onChange`; parent decides persistence. Partner notes live in form state until submit; section notes persist immediately. `SectionPanel` holds a **local optimistic copy** and **serializes saves** (promise chain + pending-ref guard) so rapid add/edit/delete never derive from a stale server prop or race — `onSaveNotes` returns the mutate promise. openapi shared `Note` schema (reused for Partner*/MeddpiccSectionMeta*; `OppNote` left untouched). DB migrated text→jsonb via psql ALTER (existing non-empty text wrapped into one `Note`, null/empty→`[]`). Section notes stay presentation-only: `companyIntel` still takes a string, so `routes/company.ts` flattens the note list (`.map(text).join("\n")`) for the AI focus.
- **Per-section workspace (owner + notes + focused AI refresh)**: Under each of the 8 MEDDPICC elements the rep can (1) pick a per-element OWNER (key person) from the opportunity's contacts or create a new contact that is auto-assigned as that element's owner, (2) add/edit/delete a list of "additional context" notes (the element's qualification guidance shows as the add-note placeholder), and (3) trigger a per-section AI refresh that focuses the company-context search using that element's **rep entries** (anchor) + owner + additional context + linked contacts + element info requirements. Persistence: `meddpicc_section_meta` table (per opportunity+element row with `notes` + `contactIds` jsonb + `ownerId` text nullable). Section refresh merges ONE focused section into `company_research.sections` (replace-in-place if present, else append) and stays presentation-only — section notes/owner/contacts/entries NEVER affect the weighted score. Backend: `companyIntel.generateSectionResearch()` (SectionFocus has owner+entries), `routes/meddpiccSections.ts` (GET list + partial PUT upsert on unique(opportunityId,element); `ownerId: null` clears), section-refresh endpoint in `routes/company.ts` (loads element entries + owner contact). Frontend: `SectionPanel` in `components/section-workspace.tsx` rendered as the right column per element in `opportunity-detail.tsx`. NOTE: section `contactIds` is still persisted and fed to the AI but no longer has a dedicated UI picker (owner replaced it).
- **Reminders (per-user)**: Simple reminders (`reminders` table: user_id FK NOT NULL cascade, name, due_at timestamptz, nullable entityType/entityId/entityLabel). All routes (`routes/reminders.ts`: GET/POST /reminders, DELETE /reminders/{id}) are scoped by the authenticated user — list filters by user_id, delete requires ownership (404 otherwise). Frontend: `components/reminder-button.tsx` (`ReminderButton` + `ReminderContext`; dialog with name + due as datetime-local OR N-days-from-now→9AM) is rendered next to every "Add a note" button carrying that note list's association: `NotesEditor` optional `reminder` prop (partner dialog, internal/partner resource dialogs, MEDDPICC `SectionPanel` via `reminderContext` prop with entityId `${oppId}:${element}`), plus inline in dashboard `NotesSheet` (opportunity context). `components/reminders-list.tsx` (`RemindersList`: collapsible card, overdue highlight, entityLabel line, delete) renders beside `InternalResources` in a 2-col grid at the top of the Partners page. Table was created via psql DDL (drizzle push hangs).
- **Resizable, size-remembering popups**: All popups (shadcn `Dialog`, `AlertDialog`, right-side `Sheet`) are capped to the viewport (`max-h-[92dvh] overflow-y-auto`) and user-resizable via a drag handle (bottom-right grip on dialogs, left-edge strip on right sheets). Shared hook `src/lib/popup-size.ts` (`usePopupSize`): persists the dragged size to localStorage keyed by `data-size-key` attribute (preferred; set on all dialogs with dynamic titles) or the popup's h2 title text, and re-applies it on next open (inline width/height + maxWidth/maxHeight overrides so saved sizes beat per-dialog `max-w-*` classes). Centered dialogs double the pointer delta (translate -50% means edges move half as fast). Drag uses pointer capture + pointercancel/blur/unmount cleanup; composed refs are stabilized via `useComposedSizeRef`.
- **AI macro web-search (three levels, presentation-only)**: "Partner Macro Info" box in the partner add/edit dialog (searches the GSI partner; result saved as a partner note), an end-customer macro card on the opportunity detail page (uses `endCustomer`, 400 if unset; result appended to opportunity notes), and an editable "Search context" textarea on each MEDDPICC element's AI refresh (optional `{context}` body on the section-refresh endpoint, threaded into `SectionFocus.searchContext`). All boxes prefill a locally-built "Suggested" context string (no extra AI call); the user can edit or reset it. Backend: `generateMacroResearch(target, kind, context?)` in `companyIntel.ts`, routes in `routes/company.ts` (POST /partners/{id}/macro-research, POST /opportunities/{id}/macro-research). Frontend: reusable `components/macro-search.tsx` (MacroSearchBox), wired into `partners.tsx` (create mode saves the partner first, then runs the search and appends the new note), `opportunity-detail.tsx`, and `SectionPanel`. Grounded Gemini JSON can be malformed (unescaped quotes; responseMimeType JSON not allowed with googleSearch) — generateMacroResearch falls back to plain-text summary + grounding-metadata sources instead of failing. Saved notes are titled "AI Macro Search — …" and remain presentation-only (never affect the MEDDPICC score).
- **Opportunity detail layout**: Landing shows a clean MEDDPICC **snapshot scorecard** (8 element tiles with letter/label/score%/mini-bar/entry-count); all elements are collapsed by default and clicking a tile expands + scrolls to that element. Team Contacts live in a dialog popup (button shows count) to save vertical space. Per element: LEFT column = rep entries (the only thing that scores), RIGHT column = `SectionPanel` AI research. Element entry dialog moved its capture/discovery guidance into the Details textarea placeholder.

- **Partner primary contact (normalized)**: `partners.primary_contact_id` FK → `partner_resources` (ON DELETE SET NULL; drizzle column declared without `.references()` to avoid circular import — constraint lives in SQL). PATCH validates the resource belongs to that partner; POST /partners rejects primaryContactId (new partner has no people yet — UI creates the resource after create, then PATCHes). Legacy `contact_name/contact_email` are read-only display-only ("Contact (legacy)" on cards / muted line in the dialog) and no longer written. Partners page dialog: Select from the partner's People (edit mode) or new-person name/email inputs that create a partner resource on save and set it as primary. Migration seeds directories from legacy `partners.contact_*` AND legacy `opportunities.partner_contact/partner_contact_role` (email-only values matched to existing resources by partner-scoped email), and backfills `primary_contact_id`.
- **Directory hygiene (dedupe + sync + name guards)**: POST /partner-resources and /internal-resources are idempotent — a create matching an existing row by normalized (trimmed, lowercased) name+email returns the existing row with 200 instead of inserting a duplicate (documented in openapi). POST/PATCH on both reject blank/whitespace names. Editing an opportunity contact that has a `directoryRef` best-effort PATCHes the linked partner/internal directory record (name/func/email/phone) so directories stay in sync — in BOTH the opportunity-detail contact dialog AND the dashboard `ContactsCell` add/edit dialog. Dashboard `ContactsCell` uses `PersonTypeahead` (scope internal for HPE column, partner+partnerId for Partner column); picking sets `directoryRef`, brand-new names are best-effort written back to the matching directory on add.
- **Central people directory (partner resources + app-wide typeahead)**: `partner_resources` table (per-partner people; same shape as internal_resources: `func`→column "function", is_manager, manager_id self-FK with same-partner + isManager + cycle checks server-side, jsonb `notes` Note[]). CRUD in `routes/partnerResources.ts`; unified `GET /people/search` in `routes/people.ts` searches internal resources, partner resources, and opportunity contacts (prefix→partner-scoped→alpha ranking; contacts deduped against directory hits by name|email). UI: `components/person-typeahead.tsx` (debounced combobox on the search endpoint, keyboard nav, source badge; empty query = browse mode — GET /people/search with empty/absent `q` returns a capped alphabetical list for the scope, so focusing an empty field immediately shows existing people) is the name field in the opportunity-detail contact dialog (picking prefills + sets `OppContact.directoryRef` = `internal:<id>`/`partner:<id>`; brand-new HPE/Partner contacts are best-effort written back to the matching directory), in the partner form's Contact Name, and in `components/partner-resources.tsx` — a collapsible per-partner "People" section (hierarchy tree, add/edit dialog like internal resources) rendered in each partner card on the Partners page.
- **Internal resources (rep's own company)**: `internal_resources` table (name, `func`→column "function", email, phone, is_manager, manager_id self-FK ON DELETE SET NULL + CHECK not-self). CRUD in `artifacts/api-server/src/routes/internalResources.ts`: managerId must reference an existing isManager resource; self-manager and multi-node reporting cycles rejected server-side (manager-chain walk); deleting a manager or clearing isManager detaches direct reports (managerId=null). UI: `components/internal-resources.tsx` rendered at TOP of Partners page — collapsible card, hierarchical list (reports nested under managers, managers-first roots, cycle-tolerant tree build), add/edit dialog with isManager checkbox + manager Select listing only managers (excluding self + own descendants). Resources also have jsonb `notes` (shared `Note[]`, edited via `NotesEditor` in the dialog, held in form state until submit; count badge in rows) and the ADD dialog offers "Start from an opportunity contact" — dedupes internal (org==="HPE") contacts across all opportunities and prefills name/function/email/phone (create-only, everything editable).
- **Stages + dashboard filters + outcomes page**: Stage enum is Qualify|Discovery|Propose|Negotiate|**Commit**|ClosedWon|ClosedLost|Dormant (Commit counts as ACTIVE). Dashboard has a global stage filter plus per-partner overrides ("inherit" follows global) that filter the active tables and show filtered revenue sums at the global bar and each partner header. `/outcomes` page (nav "Outcomes") lists ClosedWon/ClosedLost/Dormant opportunities in tabs, grouped by partner with per-partner + overall revenue totals. Partners are visually distinguished by a deterministic accent palette (`partnerAccent`/`partnerInitials` in `src/lib/partner-accent.ts`, used by dashboard + outcomes): left border, tinted header, initials chip, summary-table dot.

## Gotchas

- Never add `bcrypt` or `express-session` to api-server package.json — they're blocked by pnpm firewall
- `@google/genai` must be a direct dep of api-server (build.mjs externalizes `@google/*`, so it can't be transitive) — after adding run `pnpm install --no-frozen-lockfile`
- Gemini returns JSON with raw newlines inside strings; companyIntel.ts sanitizes via `escapeControlCharsInStrings`/`tryParse`. Thinking tokens can truncate JSON — generateContent uses temperature 0.2, thinkingBudget 4096, maxOutputTokens 24576
- After changing lib/* schemas, run `pnpm run typecheck:libs` before leaf artifact typechecks
- After codegen, no lib rebuild needed — it regenerates .ts files directly
- Seeding uses raw pg CommonJS client: `require('./node_modules/.pnpm/pg@8.20.0/node_modules/pg')`
