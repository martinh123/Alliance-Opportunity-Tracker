1. Architecture Overview

The original application is a single-page React app (Vite + TypeScript) backed by a Node/Express REST API and PostgreSQL. The WordPress rebuild replicates all functionality as a fully custom single-site WordPress application with no dependency on existing plugins.

Delivery Structure

  • Must-use plugin at wp-content/mu-plugins/gsi-tracker/gsi-tracker.php — registers all custom DB tables, REST routes, roles, and capabilities. Loads on every request before themes; cannot be deactivated from WP Admin.
  • Child theme at wp-content/themes/gsi-tracker/ — one root template (index.php) outputs the app shell HTML; all UI is rendered by the JS bundle.
  • Frontend bundle — Vite builds JS + CSS assets into themes/gsi-tracker/dist/; WordPress enqueues them via functions.php with wp_enqueue_script / wp_enqueue_style.
SPA routing: Every URL except /wp-admin, /wp-login.php, and /wp-json must return the same app-shell template. Implement with a catch-all RewriteRule in .htaccess (Apache on SiteGround). See Section 8.3 for the exact rules.

2. User Roles & Authentication

Custom Roles

gsi_adminAdminAll rep capabilities plus: manage users, org export/import, backup/restore/reset, MCP key administration.

Authentication Flow

  1. The app shell is served to all visitors. The JS router checks current-user state on load; unauthenticated visitors see only the login screen.
  2. Login: POST to /wp-json/gsi/v1/auth/login with {email, password}. PHP looks up the user by email via get_user_by('email'), verifies the password with wp_check_password(), calls wp_set_auth_cookie(), returns the user object.
  3. Session check: GET /wp-json/gsi/v1/auth/me — returns the current WP user if authenticated, else HTTP 401. The JS app calls this once on startup.
  4. Logout: POST /wp-json/gsi/v1/auth/logout — calls wp_logout(), returns {success: true}.
  5. All other gsi/v1 endpoints check authentication in their permission_callback using is_user_logged_in(). Admin-only endpoints also check current_user_can('gsi_manage_users').

Organization (Tenant) Scoping

Each WordPress user has a custom user meta field gsi_org_id pointing to a row in the gsi_organizations table. Every REST endpoint filters DB queries by the current user's org_id. Admins only see their own org's data.

// Helper — use at the top of every REST handler:
function gsi_current_org_id(): int {
    return (int) get_user_meta(get_current_user_id(), 'gsi_org_id', true);
}

REST Nonce (CSRF protection)

Pass a WP REST nonce to the frontend via wp_localize_script() so all fetch calls include the X-WP-Nonce header:

wp_localize_script('gsi-app', 'gsiConfig', [
    'apiBase'     => rest_url('gsi/v1'),
    'nonce'       => wp_create_nonce('wp_rest'),
    'currentUser' => is_user_logged_in() ? gsi_format_user(wp_get_current_user()) : null,
]);

5. Feature Specifications

5.1 Opportunity Lifecycle

Stages: Qualify → Discovery → Propose → Negotiate → Commit → ClosedWon / ClosedLost / Dormant

  • Reps can jump to any stage at any time; the order is not enforced.
  • When stage first transitions to ClosedWon, the server sets closed_won_at = NOW(). This field is never cleared, even if the stage later changes back.
  • Type is opportunity (default) or initiative. Both share the same table and detail page; the UI labels and icon differ.
  • Pipeline table supports: sort by name / revenue / close date / MEDDPICC score / stage; filter by partner, owner, stage, type; group by stage or by partner.
  • Inline edit in the table: stage (dropdown), partner, close date, revenue (single-cell click-to-edit pattern).

5.2 MEDDPICC Qualification Framework

An 8-element B2B sales qualification methodology:

  1. Metrics — Quantifiable business value the customer gains
  2. Economic Buyer — Person who controls budget approval
  3. Decision Criteria — Formal and informal criteria to evaluate solutions
  4. Decision Process — How and by whom the decision is made
  5. Identify Pain — The business problem or cost of inaction
  6. Champion — Internal customer advocate who supports the deal
  7. Competition — Competing solutions being evaluated
  8. Paper Process — Legal, procurement, and signature steps to close

Entries (per element)

Each element can have multiple rep-written entries. Each entry has: content (free text), customer_validated (boolean checkbox), relevance_score (integer 1–5 slider).

Section Meta (per element)

Each element section also carries: section-level notes (Note array), linked contact IDs, and an owner field.

Weighted Score Algorithm — implement server-side in PHP

Element weights (must sum to 100):
  Metrics:           15
  EconomicBuyer:     15
  DecisionCriteria:  10
  DecisionProcess:   10
  IdentifyPain:      15
  Champion:          15
  Competition:       10
  PaperProcess:      10

Per-element score:
  If element has no entries with a relevance_score → 0
  Otherwise → (AVG(relevance_score) across entries) / 5 * element_weight

Total meddpicc_score = SUM of all per-element scores   (range: 0 – 100)

Trigger: recalculate and UPDATE gsi_opportunities.meddpicc_score after
every MEDDPICC entry CREATE, UPDATE, or DELETE.
Critical rule: AI company research is strictly presentation-only and must never influence or modify the MEDDPICC score. Only data entered by reps (content + relevance_score) contributes to the score.

5.3 Contacts & Directories

Two directories:

  • Partner contacts (gsi_partner_resources) — people at partner organizations
  • Internal colleagues (gsi_internal_resources) — internal team members

Both share the same field structure. Both support a self-referential manager_id for org hierarchy.

Opportunities also carry an embedded contacts JSON array. These lightweight objects (name, email, phone, role, company) can optionally be linked to a directory record via linkedResourceId + linkedResourceType.

Cross-directory typeahead: A search input that queries both directories simultaneously by name/email. Results are labeled by source (partner name or "Internal"). Used to link an embedded contact to an existing directory record.

CSV / Excel Bulk Import (two-step flow)

  1. Upload file → server parses and returns: detected column headers + first 5 preview rows.
  2. User maps columns to schema fields (name, email, phone, function, location, manager).
  3. User confirms → server bulk-inserts. Response includes: created count, skipped count, and a skipped array with a reason per rejected row.
  4. Rows with broken foreign key links (e.g. invalid partner_id) MUST appear in the skipped list — never silently dropped.

5.4 Reminders

  • Personal to the logged-in user — other users cannot see or edit them.
  • Fields: name (title), due date/time, optional linked entity, optional linked company name, optional linked contact name, notes.
  • States: pending (completed_at IS NULL) and completed (completed_at is set).
  • Reminder bell in the global header shows a count badge for upcoming pending reminders due within 7 days.
  • Reminders can be created/edited/completed/deleted from: the dashboard bell, opportunity detail, contact/resource detail panels, and MEDDPICC section sidebars.
  • Editing a saved reminder supports changing the linked company and linked contact in addition to all other fields.

5.5 Company Intelligence (AI Research)

  1. When an end-customer domain is set on an opportunity, a "Generate Research" button appears on the opportunity detail page.
  2. Server calls Gemini API: produces a company overview narrative and per-MEDDPICC-element summaries with cited public source URLs.
  3. Results are stored in gsi_company_research. Status field cycles: generating → ready (or error).
  4. The UI shows a read-only panel: overview text, and an accordion/tab per MEDDPICC element with the summary and clickable source links.
  5. Reps can refresh research at any time; the previous record is overwritten.
  6. Changing the end-customer on an opportunity deletes the stored research (it is stale for the new company).
  7. Macro search: A global AI query box for open-ended research questions about any partner, opportunity, or company. Returns a narrative response. Results are not stored in the database.

5.6 Nearby Contact Search

  1. User enters a destination (e.g. "Cincinnati, OH" or informally "Cinci") and a radius with unit (mi or km).
  2. Server sends the raw string to Gemini to normalize → "Cincinnati, Ohio, USA".
  3. Normalized string is checked against gsi_geocode_cache. Cache hit → use stored lat/lon.
  4. Cache miss → call Nominatim API. Cache the result (including not-found) before returning.
  5. Compute Haversine distance from destination to every partner and internal resource in the org that has lat/lon set. Return those within radius, sorted by distance ascending.
  6. Contacts with no geocoded lat/lon are returned in a separate "unresolved locations" list.

Nominatim policy: Always include User-Agent: YourApp/1.0 (admin@yourdomain.com) header. Max 1 request per second — add usleep(1000000) between batch geocoding calls.

5.7 Dashboard Analytics

KPI Cards (Dashboard)

  • Total pipeline value — sum of revenue for all non-closed opportunities
  • Weighted pipeline — sum of (revenue × stage probability). Weights: Qualify 10%, Discovery 20%, Propose 40%, Negotiate 60%, Commit 80%, ClosedWon 100%
  • Opportunity count by stage
  • Average MEDDPICC health score across all open opportunities

Outcomes Page Charts

  • Closed-won revenue vs annual quota for the current fiscal year (using user's fiscal_year_start/end settings)
  • Pipeline value by partner (bar chart)
  • Pipeline value by stage (bar or funnel chart)
  • Win rate: ClosedWon count ÷ (ClosedWon + ClosedLost) count
  • Average MEDDPICC score at time of deal close

5.8 Administration

  • User management: Admin lists all users in the org. Create: calls wp_insert_user(), creates a gsi_profiles row, writes gsi_org_id user meta. Edit: name, email, role, quota, region. Reset password. Delete (cannot delete own account).
  • Org export/import: Admin downloads a JSON file of all org data (opportunities, partners, resources, MEDDPICC, reminders, research). Import replaces the org's data from a previously exported JSON file.
  • Full backup/restore/clear: Admin-only. Export or restore all data across all orgs. Clear wipes everything (must require confirmation).
  • MCP key: Admin views the org's MCP API key (value masked in UI). Regenerate button creates a new random key and saves it in gsi_organizations.mcp_key.

5.9 MCP Read-Only Endpoint (Claude AI Integration)

The endpoint /wp-json/gsi/v1/mcp provides read-only access to the org's tracker data for Claude AI. Authenticated by the org's mcp_key value sent as a Bearer token in the Authorization header (not a WP cookie). Returns structured data: open opportunities, partners, pipeline summary, and contact directory for the caller's org.

7.1 Google Gemini AI

Used for: company research generation, macro search, and pre-normalizing location strings before geocoding.

  • Store the API key as a WordPress option (not in code): update_option('gsi_gemini_api_key', $key). Read: get_option('gsi_gemini_api_key').

8.7 MEDDPICC Score Calculation (PHP)

function gsi_recalculate_meddpicc_score(int $opportunity_id): float {
    global $wpdb;
    $table = $wpdb->prefix . 'gsi_meddpicc_entries';

    $weights = [
        'Metrics'          => 15,
        'EconomicBuyer'    => 15,
        'DecisionCriteria' => 10,
        'DecisionProcess'  => 10,
        'IdentifyPain'     => 15,
        'Champion'         => 15,
        'Competition'      => 10,
        'PaperProcess'     => 10,
    ];

    // Average relevance_score per element (ignoring NULL scores)
    $rows = $wpdb->get_results($wpdb->prepare(
        "SELECT element, AVG(relevance_score) AS avg_score
         FROM $table
         WHERE opportunity_id = %d AND relevance_score IS NOT NULL
         GROUP BY element",
        $opportunity_id
    ));

    $by_element = [];
    foreach ($rows as $row) {
        $by_element[$row->element] = (float) $row->avg_score;
    }

    $total = 0.0;
    foreach ($weights as $element => $weight) {
        $avg   = $by_element[$element] ?? 0.0;
        $total += ($avg / 5.0) * $weight;
    }
    $score = round($total, 2);

    $wpdb->update(
        $wpdb->prefix . 'gsi_opportunities',
        ['meddpicc_score' => $score],
        ['id'             => $opportunity_id],
        ['%f'],
        ['%d']
    );

    return $score;
}

Caching — Critical

Warning: SiteGround's SuperCacher must be configured to bypass all API routes. Without this, a cached API response from one user's session will be served to another user, exposing private data.
  • Site Tools → Speed → Caching → Excluded URLs: add /wp-json/*
  • Also exclude any cookie-setting URLs (wp-login.php).
  • The SPA app shell HTML can be cached — it contains no user data.
